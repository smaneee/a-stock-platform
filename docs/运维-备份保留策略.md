# 运维：基线备份与保留策略

## 背景（实测）

备份产物每份约 **2.50 GB**（主库 `backend\a_stock.db` 约 2.68 GB，SQLite 在线备份 + SHA-256 + 只读恢复验证）。
此前每轮开发都新增一份且从不清理，2026-09-15 当天累积到 19 个目录、约 45 GB，导致 D 盘两次写满：

```
sqlite3.OperationalError: database or disk is full
```

第一次写满时留下 `20260915_182157`（1.46 GB，未完成）和 `20260915_182209`（0.00 GB，空目录）两个残留。
结论：**无界保留备份是缺陷，不是磁盘容量问题**。

## 工具

**实现（版本化，唯一真源）：`scripts/backup_baseline.py`**

| 子命令 | 用法 | 说明 |
| --- | --- | --- |
| `backup` | `python scripts/backup_baseline.py backup [keep] [dest_root]` | 在线备份 → `integrity_check` → 行数比对 → SHA-256 → 写 `backup-info.json`；成功后自动执行 prune |
| `prune` | `python scripts/backup_baseline.py prune [keep] [dest_root] [--dry-run]` | 按内容去重，只保留最新 N 份已验证且内容互不相同的备份目录 |
| `manifest` | `python scripts/backup_baseline.py manifest <dest>` | 生成目录级 `manifest.json` / `manifest.sha256` |

历史路径 `outputs/handoff/_baseline_backup.py` 已改为**转发壳**（`runpy` 调用上面的实现），
老命令继续可用，但不存在第二份实现。

默认 `dest_root = D:\A股量化平台备份`，保留份数 `keep = 3`，可用环境变量 `BASELINE_BACKUP_KEEP` 覆盖。

## 保留规则（prune 语义）

1. 只处理名字匹配 `^\d{8}_\d{6}$` 的时间戳目录，其他目录/文件一概不动。
2. 「完整备份」的判定：同时存在 `a_stock.db` 与 `backup-info.json`，且 `backup-info.json` 中
   `restore_verification == "PASS"`。仅凭目录存在不算，避免把写了一半的残留当成品。
3. **按内容去重**：同一份主库内容只保留最新那一个目录。判定重复时**重新计算实际 SHA-256**并与
   幸存者比对，不盲信 `backup-info.json` 里的记录值；记录值与实际值不符时视为独立备份并保留。
4. 最多保留最新 `keep` 份**内容互不相同**的完整备份；最新一个完整备份永不删除（keep=0 也至少留 1 个）。
5. 其余目录一律删除：内容重复的、超出份数的旧备份、以及所有未完成的残留目录。
6. 每次删除打印目录名、原因与释放空间；`--dry-run` 只列不删（此模式不做哈希复核）。

> 实测佐证：主库在未发生写入时（例如同一天结算后不再变更），连续多次备份会得到完全相同的 SHA-256。
> 2026-09-15 的三份保留备份 SHA-256 全为 `02ed00cc…a4de4d`、size 均 2,684,616,704、
> `source_mtime` 均 `2026-09-15T15:30:00`，即逐字节相同，按旧规则白占 5 GB。

## 建议操作

- 例行备份：`python scripts/backup_baseline.py backup`（自带 prune，无需手工清理）
- 清理前先看：`python scripts/backup_baseline.py prune 3 --dry-run`
- 恢复验证：读取目标目录 `backup-info.json` 的 `backup_sha256` 与 `restore_verification`，并与实际文件重新计算比对

## 2026-09-15 实际执行记录

1. 手工清理：删除 16 个目录（含 1 个 1.46 GB 残留与 1 个空目录），释放 **37.4 GB**；
   保留 `20260915_151636`、`20260915_173357`、`20260915_181748` 三个完整备份。
2. 加保留策略后重跑备份：新备份 `20260915_182319`
   （size 2,684,616,704 / `integrity_check=ok` / `foreign_key_violations=0` / 31 张表 / 行数一致 /
   `restore_verification=PASS`），自动淘汰最旧的 `20260915_151636`。
3. 加入内容去重后再次 prune：确认 `20260915_181748`、`20260915_173357` 与 `20260915_182319`
   的实际 SHA-256 相同，删除两份重复，再释放 **5.0 GB**。
4. 现状：备份目录只剩 `20260915_182319`（2.50 GB，已验证），D 盘剩余 **42.4 GB**；此后无需手工清理。
