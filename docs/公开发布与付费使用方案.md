# 公开发布与付费使用方案

## 目标

把 `a-stock-platform` 从私有交付仓库调整为公开展示项目：让别人能看到完整工程能力、复现本机研究流程，并通过低门槛赞助支持持续维护。

## 推荐模式

不要把公开 GitHub 仓库设计成“必须付费才能 clone”。公开仓库天然适合传播、展示能力和积累 star；收费应放在便利服务和授权边界上。

推荐采用：

1. 公开源码：任何人可以浏览、clone、学习和提交 issue。
2. 低门槛赞助：GitHub Sponsors 设置 0.5 美元支持档；如果后台不接受 0.5 美元，就设置 1 美元档。
3. 付费便利包：提供一键安装包、初始化脚本、演示数据包、部署指导、更新支持。
4. 商业授权：企业内部分发、二次销售、托管服务或付费部署，需要单独联系作者。

## GitHub 页面要做的事

1. 在仓库 Settings -> General -> Danger Zone 中把仓库从 Private 改成 Public。
2. 打开 GitHub Sponsors，创建一个低价支持档。
3. 在仓库 About 里填写：
   - Description: `A Stock quantitative research platform`
   - Website: 可先留空
   - Topics: `a-share`, `quant`, `fastapi`, `react`, `backtest`, `stock-research`
4. 开启 Issues，用于收集问题和需求。
5. 等项目稳定后再开启 Discussions，用于沉淀使用经验。

## README 表达原则

- 先展示能力：实时行情、股票池、历史入库、回测、样本外验证、模拟盘、DeepSeek 解释层。
- 明确边界：不荐股、不承诺收益、实盘默认关闭。
- 强调研究纪律：样本外验证、负结果保留、无证据不通过。
- 付费表达要克制：赞助是支持维护，付费便利包是节省配置时间。

## 不建议

- 不建议承诺“支付 0.5 美元即可获得收益策略”。
- 不建议把自动交易当卖点。
- 不建议上传数据库、个人密钥、真实账户截图或完整研究输出。
- 不建议一开始就把商业授权条款写得过重，否则会降低公开传播效果。

## 下一步

公开后先观察一周：star、issue、clone、用户提问。如果有人愿意试用，再补充英文 README、截图、安装视频和 release 包。
