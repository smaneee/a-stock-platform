# A 股个人量化平台研发计划（2026 Q4）

**版本：** v1.1（证据与可执行性复审）

**制定日期：** 2026-09-13

**建议开发窗口：** 2026-09-14 ～ 2026-12-06（12 周参考排期，非交付承诺）。首周核定工作量和实际投入后滚动调整；前向观察按真实交易日累计，独立于开发排期。

> 本计划的目标是构建可审计、可复现、风险受控的 A 股研究与交易辅助软件，不承诺收益，也不把任何排名或模型输出表述为“必涨”或“最好”。所有研究结果仅用于研究，不构成投资建议。

## 1. 当前事实与研发决策

### 1.1 已具备能力

- 全市场沪深京股票池、前复权日线、东方财富数据中心、涨停情绪池、技术指标、实时分时、回测、模拟盘、手机响应式页面和桌面启动器均已具备基础实现。
- 上轮本地快照筛选池约 5,550 只；历史日线覆盖 2021-03-25 以来 1,328 个交易日。这是本地记录口径，不代表已逐只核验交易所完整名单、实时交易资格或用户账户权限。
- 涨停情绪池已落库，包含封板率、炸板率、连板高度、涨跌停家数和封板金额等字段。
- 上轮记录为 988 项后端自动化测试通过（2026-09-13）；本次只复审计划与依据，没有重跑业务测试。单测数量不能替代真行情、移动真机和券商联调验收。

### 1.2 已验证的限制（必须如实展示）

- 买点雷达在 6 个滚动样本外留出段中，3 日持有平均超额收益为 **-0.390%**，仅 1/6 折为正；当前规则不具备上线为实盘选股策略的资格。
- 训练段调权重后，留出段平均超额收益为 **-0.714%**，存在明确的过拟合迹象。
- 情绪因子结论撤回为“待复核”：`work/ps_search/sent_factor.py` 查询行情未显式按日期排序，却用返回顺序推进未来收益；Spearman 使用两次 argsort，未给并列值平均秩；使用当日收盘情绪与同日收盘起算收益、混合来源且未校正重叠收益。现有相关系数不构成可交易预测力证据，不能据此调整仓位。
- 六折超额数字来自现存 `wf_summary.json`，是各折平均持有期超额的算术平均，不是账户累计收益或年化收益。平均 t 值不是合并显著性检验；30 次随机对照的最大值不是正式显著性临界值。保留负结果，但不能推论所有策略永久无效。
- 当前历史股票池快照仍不完整，存在幸存者偏差风险；历史北交所成分缺失时必须拒绝生成“完整历史快照”。

### 1.3 立即决策

1. 保留“买点雷达”，但产品文案改为“研究候选排序”，默认显示“当前未通过样本外超额验证”。
2. 本期实盘开关默认关闭。券商密码不进入软件或对话；必要的账户标识按最小化原则在本机管理、日志脱敏。接入资格、费用、接口与账户权限均须向具体券商核实。
3. 现有 QMT 适配代码是待联调候选，不代表该账户已能使用，也不代表唯一合法通道。实盘独立验收、逐笔人工确认、限额并审计；撤单只对可撤委托生效，不能承诺撤回已成交交易。
4. 策略研发与产品功能研发分轨推进；任何策略未通过验证都不得提升为“买入推荐”。

## 2. 成功定义与不可妥协的门槛

| 维度 | 成功定义 | 上线门槛 |
| --- | --- | --- |
| 数据真实 | 每个报价均可追溯来源、市场日期、接收时间和延迟 | 非交易日不伪造实时行情；异常/过期报价不参与信号 |
| 数据完整 | 股票池、历史行情、复权、停复牌、企业行为口径一致 | 覆盖不足或历史快照缺交易所时拒绝给策略结论 |
| 策略有效 | 多市场阶段、预注册实验、可执行组合扣费后的样本外表现 | 按第 11 节评审；取消“12 折、8/12 为正”作为充分条件，样本不足返回不确定 |
| 风险可控 | 仓位、损失、回撤、订单状态和异常均可拦截 | 模拟盘连续 60 个交易日无高危订单状态错误；所有风控拦截可追溯 |
| 可用性 | 桌面与移动浏览器均可稳定操作 | 定义页面成功事件和统计分母；目标失败率 < 1%，同时报告样本数、时段、网络和设备，少量手工访问不算达标 |
| 安全 | 凭据不进入业务数据、日志和导出 | 本机安全配置管理；局域网身份校验、写接口授权、会话过期和实盘确认均需测试 |

> “策略通过”不是“保证盈利”。通过门槛后也只表示获得小额、受控模拟或人工确认实盘的资格。

## 3. 产品范围

### 3.1 本期必须完成

- 真实数据状态中心：交易日、开闭市、数据源、接收时间、延迟、最新行情时间和降级状态。
- 全市场数据质量体系：股票池覆盖、日线缺口、复权覆盖、涨停情绪覆盖、历史快照覆盖的自动检查与报告。
- 研究策略实验室：因子版本管理、训练/验证/留出严格隔离、滚动样本外验证、交易成本、随机对照、结果归档。
- 市场情绪因子：封板率/连板高度曲线、滞后参数、分层回测、市场状态标签和仓位缩放实验。
- 模拟盘闭环：每日候选、次日可成交性、持仓、风控、成交回报、归因和对账。
- 首页研究候选区：只显示数据新鲜度、市场状态、策略版本、验证状态和候选排名；未通过验证时显著禁止“推荐买入”表述。
- 移动端与桌面启动器：同一功能集、网络状态、刷新状态、异常提示和启动诊断。

### 3.2 本期明确不做

- 不做东方财富账号密码登录、抓取或自动下单。
- 不做“稳赚”“现在买哪只最好”“保证涨停”等承诺性功能。
- 不用未验证 GitHub 爬虫绕过登录、验证码、付费墙或数据源访问限制。
- 不把单次回测、单一年份收益或未扣交易成本结果用于策略上线。

## 5. 工作分解

### 5.1 数据与行情（P0）

1. 分开记录源行情时间、服务器接收时间、客户端展示时间、请求耗时、来源及时间精度。轮询间隔、扫描耗时、行情年龄不是同一指标；源时间缺失时行情年龄标为未知，不把接收时间冒充交易所时间。
2. 交易日历按北京时间维护午间休市、周末、节假日和临时休市；非交易日只展示最近交易日收盘数据。
3. 先实测现有 TDX、东方财富、腾讯、AKShare 的市场覆盖、交易时段延迟及失败率，再按数据类型配置优先级。封装库共享同一上游不算独立备援；不得宣称免费源不限流或保证固定秒级延迟。
4. 日线、分钟线、复权数据分别做完整率、连续性、重复率、极端值和数据源一致性校验。
5. 建立数据质量日报，写入 `outputs/quality/`；任何指标缺覆盖率不得进入回测。

### 5.2 股票池与企业行为（P0）

1. 以交易日快照作为回测股票池唯一入口，保留上市、退市、停牌、ST、北交所状态和来源证据。
2. 覆盖要求由回测声明的市场范围及该日期实际已存在的市场决定。全 A 回测缺必要市场则失败；可单独运行明确标注范围的沪深研究，不能冒充全 A，不能把当前北交所名单拼入历史。
3. 前复权数据以除权除息事件为依据，保留因子、原始价、复权价与复核记录。
4. 为退市、长停、代码变更、上市初期无涨跌停限制等边界建立回归测试。

### 5.3 策略研究与验证（P0）

1. 所有策略登记唯一版本：代码提交、参数、数据截止日、股票池快照、复权口径、费用、滑点、结果文件。
2. 固定研究流程：假设 → 训练 → 隔离带 → 留出 → 滚动验证 → 随机对照 → 成本敏感性 → 结论。
3. 把“连板高度”作为候选市场状态特征单独验证；封板率不得因直觉直接赋高权重。
4. 增加行业中性、规模分组、市场风格分段、牛熊/震荡分段与事件日剔除实验，检验收益是否由单一时期驱动。
5. 在包含资金占用、现金、重叠持仓、公司行为与成交约束的账户净值上计算累计/年化收益、回撤、波动、换手和尾部风险；禁止把重叠的多日持有收益直接连乘为净值。
6. 未达到第 2 节策略门槛前，首页只可标记为“观察候选”，不得显示“买入建议”。

### 5.4 模拟盘与实盘安全（P0）

1. 模拟盘按真实 A 股规则执行：T+1、涨跌停、停牌、最小佣金、印花税、滑点、部分成交和撤单。
2. 每日收盘自动对账：候选 → 下单意图 → 模拟成交 → 持仓 → 当日盈亏 → 次日可卖数量。
3. 风控硬拦截：单票仓位、总仓位、单日亏损、组合回撤、行情超时、数据源降级、异常价格与重复委托。
4. 实盘通道仅保留 QMT 适配层：默认关闭、账户只读对账、一次性确认令牌、逐笔人工确认、订单状态 UNKNOWN 不自动重试。
5. 实盘试点前必须完成连续 60 个交易日模拟盘，并由发布评审签字确认。

### 5.5 前端、移动端与可观测性（P1）

1. 首页增加“研究状态条”：交易日状态、行情延迟、最新数据时间、数据源、策略验证状态和风险等级。
2. “现在买什么”改名为“研究候选排名”，每张卡必须显示数据时间、候选理由、失效条件、风险标签及“未验证/验证中/通过”状态。
3. 手机端优先保证：首页、候选、分时、持仓、模拟盘、风险告警；表格默认卡片化，明细表可横向滚动。
4. 建立运行指标：接口错误率、数据源成功率、行情延迟分位数、任务耗时、WebSocket 连接数、回测失败原因。
5. 桌面启动器提供版本、数据库状态、端口、日志、数据质量最后更新时间和一键导出诊断包。

### 5.6 安全、备份与发布（P0）

1. 真实账号、密码、令牌不得写入源码、日志、数据库、导出文件或前端；已泄露的凭据必须立即在券商端轮换。
2. 本机 `.env` 仅保存必要配置，生产密钥使用操作系统凭据/受控秘密管理，不进入 Git。
3. 每日一致性备份、每周恢复演练，先测 SQLite 锁等待、写入失败率、磁盘空间与恢复时间。只有并发写入等实测瓶颈无法满足目标时才迁移 PostgreSQL，避免强制增加运维依赖。
4. 每次发布执行：迁移演练、全量测试、API 冒烟、桌面启动器冒烟、移动端关键路径检查、回滚方案演练。

## 7. 关键验收用例

1. 周末打开首页：明确显示“今日休市”和最近交易日；不显示“实时可交易”。
2. 行情源失效：页面显示来源降级与最后有效时间；过期行情不能生成交易意图。
3. 历史北交所快照缺失：回测拒绝运行并指出缺失市场，不能偷偷混入当前股票池。
4. 除权日：未复权涨跌停判断与前复权策略收益口径各自正确，且不可互用。
5. 研究参数变更：报告能追溯代码、数据、参数、股票池、费用和随机种子。
6. 对缺少盘口排队证据的涨跌停成交采用保守假设，区分一字板与盘中开板，不能把“触及涨停/跌停”机械等同全天无法成交；停牌、T+1、部分成交、重复请求均单独验收。
7. 移动网络切换和页面后台恢复后，WebSocket 重新连接且状态可见。
8. 实盘开关、确认令牌、风控上限和审计记录缺任一项时，委托请求必须失败。

## 8. 风险台账

| 风险 | 影响 | 防控措施 | 触发后的动作 |
| --- | --- | --- | --- |
| 免费数据源限流/变更 | 实时性和完整性下降 | 多源回退、缓存、限流、来源展示 | 降级为只读历史数据并停止生成候选 |
| 幸存者偏差 | 回测虚高 | 交易日快照、缺交易所即拒绝 | 标记研究无效，不允许策略晋级 |
| 过拟合 | 看似有效、实盘失效 | 多折留出、随机对照、参数登记 | 回退到研究状态，禁止实盘 |
| 交易成本低估 | 收益虚高 | 佣金/税/滑点/涨跌停/容量敏感性 | 重跑回测，未通过则下线 |
| 凭据泄露 | 资金与隐私风险 | 不存密码、日志脱敏、环境变量 | 立即轮换、停用通道、审计影响范围 |
| 单机 SQLite 锁竞争 | 任务失败或数据损坏风险 | 队列化写入、备份、WAL 监控、迁移 PostgreSQL | 停止写任务、恢复备份、复核一致性 |

## 9. 发布判定

### 9.1 12 周结束时必须交付

- 可复现的数据质量报告与策略研究报告。
- 真实数据状态中心、研究候选排名、情绪因子曲线、模拟盘闭环与移动端关键流程。
- 前向模拟运行记录、实际累计交易日、缺陷与修复证明；目标 20 日，版本冻结较晚或发生影响成交的重大修复时顺延观察，不能用开发截止日期倒推达标。
- 全量自动化测试、API 冒烟、启动器自检和恢复演练结果。
- 真实交易准入评审表；未达到门槛时明确结论为“仅研究与模拟”。

### 9.2 实盘准入的额外门槛

1. 策略达到第 2 节的多折样本外门槛，且包含成本与滑点压力测试。

### 14.15 第六轮：盘前真实采样、代理坑与覆盖率门禁（2026-09-14 上午）

#### 重要环境发现：Python httpx 会走 Windows 系统代理，导致本机接口返回 502

**结论**：全市场扫描 P95 从 66.3 秒降到 **9.7 秒，已回到研发计划 12.1 的 15 秒目标以内**。

**口径诚实说明**：两次采样分属不同时刻（09:33 开盘高峰 vs 09:53），行情阶段负载不同，因此「p95 66.3s→9.7s」**不是受控 A/B**；但「日线阶段 6.0s → 0.0s」是同一时段内针对同一参数改动的**直接受控测量**，修复因果明确。行情阶段（5.3s，峰值可达 12s+）仍是主要成本与波动来源，后续若要进一步压缩需优化行情抓取批次与降级策略。

### 14.21 第十二轮：D5 部分成交与容量（2026-09-14 上午）

### 14.25 D5 容量 → 账户规模换算（2026-09-14）

**原缺口**：`capacity_multiple` 只回答「这一笔超没超容量」，不回答「这个策略最多能管多少钱」。⚠ 并且 §14.21 / §14.22 里写的「换算公式已写在 `capacity_multiple` 文档中」**不成立** —— 该 docstring 只定义倍数本身，从来没有 AUM 公式。本轮先纠正这句错话，再实现公式。

**公式（写进 `sustainable_aum` docstring）**：某笔成交发生在账户净值 `E`（**成交日**净值）下、委托 `q` 股，参与率上限下当日可成交 `cap = volume × rate`。账户放大 `s` 倍时同权重同价格下委托量变为 `s·q`，要求 `s·q ≤ cap` ⟺ `s ≤ cap/q = capacity_multiple`。逐笔算 `E × multiple` 取最小：

```
max_aum = min over trades ( 成交日账户净值 × capacity_multiple )
```

用**成交日净值**而非初始资金做基数：`q` 由当日账户规模与目标权重推出，用初始资金会在盈亏后系统性偏差（真实数据里成交日净值 ¥1,038,688 > 初始 ¥1,000,000）。

**实现**：`app/portfolio/engine.py` 新增纯函数 `sustainable_aum(trades, dates, equity_curve)` → `max_aum` / `binding_trade` / `basis` / `considered_trades` / `assumptions`；进 `PortfolioResult.capacity` 与 `to_dict()`。未启用参与率上限时返回 **None**（不得当成容量无限）。前端「结果口径」区块显示规模上界与最紧的一笔。

**这是上界不是承诺**（随结果返回）：① 无市场冲击假设；② 只统计已实现成交（被整笔拒绝的委托不在内，真实上限可能更低）；③ 未叠加涨跌停/停牌对可成交量的限制。

**真实数据实测**：三只真实日线、`rate=0.001`、120 笔成交全部参与换算 → `max_aum=¥513,730.92`，最紧一笔为 2026-09-10 000006 SELL 11,800 股（倍数 0.4946，当日净值 ¥1,038,688.33），手算校验一致。

**测试**：`backend/tests/test_execution_capacity.py` 新增 4 条（手算最小值对照、未建模返回 None、脏数据跳过不崩、引擎级恒等式），该文件合计 17 条。
